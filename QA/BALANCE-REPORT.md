# 은총 경제 / economy-qa-6 밸런스 검증

2026-11-16. 기본 근무 시간 5분 유지. 10분은 설명을 읽는 첫 플레이와 장기 전략 비교 대상으로 함께 검증했다.

## 이번 적용

- 첫 성공 보상 10 은총으로 복사의 은총(8)을 바로 살 수 있다. 두 개의 시선·말씀 자동완성은 각 12, 수련 각 1초. 초반에 입력 방식이 빠르게 달라진다.
- 일괄 2.6배 가격 증가를 없애고, 각 스킬의 각 단계에 별도 가격을 지정했다. 초반 편의와 후반 배율의 가격 곡선을 분리했다.
- 메아리 300 / 1,000 / 3,500, 성실의 배당 700 / 2,200 / 6,500, 전도 대각성 2,200. 메아리는 실적과 은총을 증폭하고, 성실의 배당은 은총을 늘린다. 최종 단계까지 쌓을지, 다른 생산 기반에 먼저 투자할지가 갈린다.
- 주소 연동과 다중 전도의 배타적 선택, 선행 스킬 최대 단계 조건을 유지했다. 여기서 ‘전 스킬 완료’는 선택한 경로에서 획득 가능한 모든 단계 완료를 뜻한다. 서로 배제된 양쪽을 동시에 사는 뜻이 아니다.
- 무작위 7% 확률의 은총 5배 대신, 성공한 발송 작업 12회마다 해당 보상 2배. 인원 12명이 아니라 성공 작업 횟수다. 피버·연속 성공은 유지했다.
- 스킬 구매 시 진행 중인 대리 천사의 발송이 사라지던 문제를 수정했다. 수련 중에는 멈췄다가 이어진다.
- 성공 판정 난수를 화면 장식용 난수와 분리했다. QA 기록에 판별용 시드를 남겨 같은 조건의 테스트를 재현할 수 있다. 실제 게임은 매 근무 새로운 시드를 사용한다.
- 앞으로 QA에는 입력란에 머문 시간, 입력 이벤트 수, 붙여넣기 횟수, 스킬창 닫기를 추가 기록한다. 입력한 주소·본문 원문은 기록하지 않는다.

## 사람 기록에서 사용한 속도

입력 파일: `heaven-qa-2026-11-15T17-47-02-156Z.json`. 중도 진입/초기화 기록을 제외한 완료된 5분 세 판을 분석했다. 성공 36 / 34 / 32명, 입력 오류 8 / 4 / 2회. 한 사람이 서로 다른 버전을 플레이한 자료이므로 일반 인구의 평균은 아니다.

연속 수동 발송 사이에서 전송 대기 시간을 빼고, 도중에 탐색·스킬 구매·스킬창 열기·입력 오류가 있는 구간과 스킬 구성이 바뀐 구간을 제외했다.

| 단계 | 사용 구간 수 | 남은 조작·판단 시간 중앙값 |
|---|---:|---:|
| 기본 입력 | 9 | 4.40초 |
| 본문 복사 | 4 | 3.60초 |
| 두 창 | 9 | 1.25초 |
| 본문 자동완성 | 33 | 1.64초 |
| 선택 주소 연동 | 14 | 1.82초 |

이 값은 순수 타자 시간이 아니다. 창 이동·복사·클릭·판단이 포함된다. 두 창 표본은 적어 모델에서는 보수적으로 1.8초를 사용했다. 두 창보다 자동완성 표본이 느린 것을 스킬의 역효과로 해석하지 않았다. 스킬창 열기→구매의 22구간 중앙값은 약 2.5초이며 모델은 2.57초를 사용했다.

관측 속도 모델을 중심으로 숙련자는 조작 0.65배·스킬 읽기 0.7초, 초보자는 조작 1.45배·읽기 7초로 가정했다. 새 기능의 미래 조작 시간은 추정치다. 오류는 추가 조작 시간으로 모델링했으며, 잘못된 문자열을 실제로 타이핑하는 에이전트는 아니다.

## 자동 플레이 결과

이전 설정 1,200판 + 최종 설정 3,000판 + 읽기 시간 민감도 300판 = **4,500판**. 중간 후보 탐색은 이 숫자에서 제외했다.

화면·소리만 생략하고 실제 `mail-game.js`의 시간 진행, 전송, 보상, 구매, 선행 조건, 재모집, 자동화 함수를 실행했다. 최종 설정은 3가지 속도 × 5가지 구매 경로 × 5/10분 × 100개 시드. 기본 시뮬레이션에서 내부 입력 검증 오류는 없었다.

아래 점수는 각 조건의 100판 중앙값이다. 이전 값은 40판 중앙값이며 가격뿐 아니라 보너스 규칙과 자동 발송 보존 수정도 포함한 전체 변경 전후 비교다.

| 경로 | 관측 속도 5분: 이전 → 변경 | 관측 속도 10분 | 초보 10분 | 숙련 5분 전 스킬 완료 |
|---|---:|---:|---:|---:|
| 주소 연동 우선 | 32 → 231 | 20,815 | 5,850 | 73/100 |
| 다중 전도 우선 | 87 → 525 | 22,048 | 6,598 | 94/100 |
| 비싼 자동화 직행 | 45 → 129 | 14,931 | 3,570 | 0/100 |
| 메아리 우선 | 43 → 68 | 18,438 | 909 | 100/100 |
| 자동화 혼합 | 35 → 301 | 21,951 | 10,556 | 98/100 |

숙련 5분에서 네 경로는 73~100%가 모든 가능한 스킬 단계를 완료했다. 하지만 첫 플레이에서 무조건 완성하게 만든 것은 아니다. 관측 속도 5분은 아직 성장 중이며, 10분에는 모든 경로가 완료했다. 초보 10분에서는 경로에 따라 약 909~10,556점으로 차이가 컸다.

‘비싼 자동화 직행’은 초반에 대각성을 살 돈부터 기다리는 비효율적 비교 경로다. 자동화 전략 전체가 약하다는 뜻이 아니다. 혼합 경로는 초보에게 특히 강했다. 이미 모든 생산 기반을 완성한 숙련자의 10분 점수는 주소록 보충 속도 한계에 수렴하므로 5분보다 경로 차이가 작다.

읽기 시간 추가 검사(초보 조작 속도, 10분, 조건당 50판):

| 스킬 하나 읽는 시간 | 다중 전도 점수 / 완료 | 혼합 점수 / 완료 |
|---|---:|---:|
| 4초 | 15,047 / 50판 | 15,901 / 50판 |
| 10초 | 1,382 / 0판 | 4,500 / 31판 |
| 15초 | 111 / 0판 | 128 / 0판 |

읽기에 오래 걸리면 확실히 느려진다. 설명을 처음 읽는 사람까지 5분 만렙으로 맞추면 숙련자는 후반의 구매 판단이 사라지므로, 초보 10분과 숙련 5분을 서로 다른 목표로 두었다.

## 검증 및 한계

- 가격표와 실제 게임 일치, 모든 단계 구매·차감, 선행 최대 단계, 배타 경로, 고정 보너스, 동일 시드 결과, 진행 중 자동 발송 보존: **199개 확인 통과**.
- 실제 Chrome: QA 기록/내보내기/재로드 보존/개인 입력 비기록, 두 루트의 자동입력과 합류 조건, 일시정지, 대리 천사 아래부터 발송, 첫 행 보호, 자동완성 버튼 숨김, 재모집 페널티, 스킬 버튼 눌림 크기 유지 통과.
- 후반 전체 스킬 Chrome 검사: 약 12.7초 동안 자동 발송으로 실적 1,528, 은총 32,520. 주소록 범위 정상, 화면 오류 0건. 금빛 보상 연출과 큰 숫자의 사이드바 표시도 확인했다. 이 검사는 기능 확인이며 장시간 성능 보장은 아니다.
- 제공한 기존 사람 로그의 장부 검사 통과. 새 가격 설정의 브라우저 로그도 장부 검사 통과.
- 모델은 경로를 미리 알고 구매하며, 주소를 찾는 시각적 부담과 설명 이해의 차이를 완전히 재현하지 않는다. 다음 영혼 이후 최대 인원 선택도 낙관적인 가정이다. 화면·오디오 성능 부하를 4,500판 동안 재현한 것은 아니다.
- 실제 참가자 점수나 완주율에 대한 보장은 아니다. 다음 사람 QA에서 첫 복사/주소 연동/다중 전도/첫 메아리 시점과 읽기 시간을 비교해야 한다. 현재 기록은 덮어쓰지 않았고 새 버전 표시로 구분된다.

## 다시 실행

Node.js로 프로젝트 폴더에서:

```powershell
node QA/economy-regression.cjs
node QA/balance-core.cjs QA/balance-economy-6.json 100 QA/simulation-latest.json
node QA/balance-sensitivity.cjs
node QA/calibrate-input.cjs "사람-QA-기록.json"
node qa-analyze.cjs "사람-QA-기록.json"
```

`balance-paths.cjs`에서 구매 순서를 바꿔 경로를 비교할 수 있다. 가격 후보는 JSON 복사본으로 넣는다. 이 도구는 게임 파일을 자동 덮어쓰지 않는다. 최종 결과는 `results-economy6-3000.json`, 이전 실행 결과는 `results-before-1200.json`, 읽기 검사는 `sensitivity-results.json`이다. 이전 결과는 당시 코드의 보관 결과이며 현재 코드에 이전 가격만 넣는 것은 완전한 과거 버전 재현이 아니다.

브라우저 검사는 Playwright가 필요하다. `PLAYWRIGHT_MODULE`을 설치된 모듈 경로로, 필요시 `CHROME_PATH`를 Chrome 실행 파일로 지정한 뒤 `browser-qa.cjs`, `browser-routes.cjs`, `browser-regression.cjs`, `browser-endgame.cjs`를 실행한다. 브라우저 검사는 화면과 파일을 현재 작업 폴더에 저장한다. 테스트용 상태 주입은 테스트에서만 실행되고 배포 게임에는 포함되지 않는다.
